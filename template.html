    sealed links

    Only people with the code can read it

    A sealed link is encrypted with a code. Chat apps, link previews and browser history only see scrambled text. Without the code, nobody can read the address, amount or memo.

    • Send the link and the code separately: the link in a DM, the code by voice or in another app.
    • The generated 12-character code is the strongest. Your own code can be 8 to 12 letters or numbers. Longer is safer, and avoid words or dates.
    • Everything is encrypted on your device. The code never leaves it.

    guide

    How zkSEND works

    Make a link, share it, get paid. Everything happens in your browser, and the payment goes straight from one wallet to another.

    Get paid

    1. Paste a shielded address. Use a fresh one from your wallet for each request. zkSEND checks it for typos and refuses transparent addresses.
    2. Add an amount and what it's for. Both are optional. A private memo like ZECINV-ab12cd is made for you, and the link expires after 24 hours unless you choose otherwise.
    3. Share the link. Everything about the payment lives after the # in the link, which browsers never send to the server.
    4. The payer scans the QR code or taps "open in wallet". The address, amount and memo are filled in for them. Noir users can pay in one click.
    5. Watch it complete. The payer taps "I sent it" and pastes the transaction ID. A progress bar follows the payment through 10 confirmations, and either of you can open the same tracking link.

    Tip jars

    A permanent link you can pin in a bio or on a site. Tippers pick an amount and can add a private message, which travels in the encrypted memo. Tip links never expire; if you change address, make a new link and update it everywhere you posted the old one.

    Pay many

    For payroll, bounties and payouts. Paste one line per person (address, amount, memo), straight from a spreadsheet if you like, and pay everyone in a single shielded transaction. If a wallet can't do multi-payment links, pay one person at a time from the same page. After paying, each person gets their own tracking link that shows only their payment.

    Sealed links

    Turn on "seal this link" and the whole link is encrypted with a code, so chat apps, link previews and browser history only see scrambled text. Send the code separately: a different app, a call, or in person. Tracking links made from a sealed link stay sealed with the same code.

    Checkout and pay buttons

    Every link comes with a ready-made HTML button for a site and a Markdown link for Discord or GitHub. Shops can also build links themselves; see the FAQ for the format.

    faq

    Questions

    Short answers about privacy, payments and how zkSEND works.

    Privacy

    Does zkSEND store any data?

    No. There is no database and no account system. zkSEND saves nothing about you or your payments: no addresses, amounts, memos, messages or transaction IDs. Every request, tip jar and tracking link carries its own details inside the link, after the #, and browsers never send that part to our server.

    Can the developers see my payments?

    No. The developers have no access to any payment, address, amount, memo or transaction, because none of it ever reaches zkSEND's server. The one thing that exists, as with any website, is the hosting provider's basic connection log: when the page was loaded, from which IP address, with which browser. It never contains payment details. The developer can see that log in the hosting dashboard; use Tor if you'd rather not share your IP.

    Does zkSEND ever touch my funds?

    Never. Payments go straight from the payer's wallet to the recipient's wallet. zkSEND only builds the payment link. It never holds keys or funds, can't move or freeze money, and takes no fees.

    What is a sealed link?

    A link that's encrypted with a code, so only people with the code can see what's inside. Chat apps, link previews, browser history and zkSEND's server only ever see scrambled text. Send the link and the code separately, for example the link in a DM and the code by voice. Everything is encrypted and decrypted on your device with AES-256, and the code never leaves it. The generated code is 12 characters; you can also choose your own of 8 to 12. Payment links, tip jars and pay-many lists can all be sealed, and tracking links made from a sealed link stay sealed with the same code.

    What still links me to a payment?

    The app you paste a link into can read it. So can your browser history and anything that syncs it. Reusing one address, your writing style, and paying from a wallet you also use personally can also connect the dots. Tor or a separate browser profile helps with the IP address.

    Why did I get a "checking your browser" page?

    Too many requests arrived from your network, or the site is under load. Your browser solves a small puzzle to prove it isn't a script. No third-party captcha is involved. The pass it earns is tied to your network for an hour and isn't recorded anywhere.

    Payments

    How does the progress bar work?

    After paying, tap "I sent it" and paste the transaction ID from your wallet's history. The page then goes from searching the network, to confirming (1 to 10), to complete. The progress lives only in your browser tab and the link. Send the tracking link to the other person, and they can watch the same progress.

    Why do I have to paste a transaction ID?

    Shielded payments hide who paid whom, how much, and the memo, from everyone except the recipient's wallet. That includes zkSEND. Sites that find your payment automatically can do it because they are the recipient and hold their own viewing key. zkSEND isn't, and doesn't want your keys, so it follows the one thing that's public: the transaction ID.

    What happens to tracking data when a payment completes?

    There's nothing on our side to delete, because nothing was ever stored. Tracking stops at 10 confirmations. "Clear this page" removes the payment from your address bar, and an open tab clears itself 4 hours after completion. Copies of the link you sent someone stay in that chat until you delete the message.

    What if a payment doesn't go through?

    If a payment isn't confirmed within about an hour, it expires and the funds become spendable in the payer's wallet again. The progress bar will say it can't find it. The only risk is paying twice while the first one is still pending, so wait before retrying.

    Which wallets work with zkSEND?

    Any Zcash wallet that can scan a QR code or send to a shielded address with a memo, which covers all the major ones. "Open in wallet app" works with wallets that register Zcash payment links on your device, including current versions of Zodl on iPhone and Android. If nothing opens, update your wallet or scan the QR code from inside it. On a computer with the Noir browser wallet installed, a "pay with Noir" button appears, and the progress bar starts by itself after you pay.

    Does "pay many" really send one transaction?

    Yes, if your wallet supports multi-payment links (ZIP 321). If yours opens only the first payment, use "pay this one" for each person instead; the list lets you tick them off as you go.

    Can I use this for checkout on my shop?

    Yes. Create a request, open "put a pay button on your site", and paste the HTML. Shops can also build links themselves: https://zksend.net/#u=ADDRESS&a=AMOUNT&m=ORDER-ID&n=LABEL&x=EXPIRY, where x is an optional expiry time in Unix seconds. Use a fresh address per order, and match payments by the order ID in the memo.

    Is there a fee?

    No. zkSEND takes nothing from any payment. If it's useful to you, there's an optional "tip the dev" button at the bottom of every page.

    security

    Threat model

    What zkSEND protects, exactly who can see what, and what it can't protect you from.

    In short

    • Payment details live only inside the link, after the #. Browsers never send that part to any server.
    • zkSEND has no database, no accounts and no analytics, and writes no request logs.
    • zkSEND never holds keys or funds. Payments go directly from wallet to wallet.
    • Sealed links hide the details even from the apps the link passes through.

    How it's enforced

    • Fragment-only data. Every request, tip jar, pay list and tracking link keeps its details after the #, which is never part of a web request.
    • A locked-down page. A strict Content Security Policy lets the page contact exactly one outside address, Blockchair's API, and only when you track a payment. Scripts and styles are pinned by hash, fonts are embedded, and no third-party code runs.
    • Nothing to leak. There's no database. The server prints one line when it starts and logs no requests.
    • Bot protection without tracking. Rate limits use in-memory keyed hashes of IPs under a key that rotates hourly. The proof-of-work pass is a keyed hash too, stored nowhere.
    • Sealed links. Encrypted in your browser with AES-256-GCM, using a key stretched from the code with PBKDF2-SHA256: 200,000 rounds for generated codes, 600,000 for codes you choose. Any change to the link makes it refuse to open. The code never leaves your device.
    • Checked payment links. Addresses are checksum-verified, and every payment link follows ZIP 321 and is tested against the reference parser from librustzcash.
    • Open source. The full source is public, so anyone can check exactly what runs.

    What zkSEND can't protect against

    • A compromised device. Malware or a malicious browser extension can read any page you open.
    • Fake links. Anyone can make a zkSEND link. Before paying, confirm with the person asking that the address starts and ends the way the pay page shows.
    • The site itself. Like any web app, you trust the code the server delivers each time you load it. The source is public, and the page's scripts are pinned by hash.
    • Guessable codes. Someone holding a sealed link can try codes offline. The generated 12-character code is out of reach; a short code you choose, especially a word or a date, is not.
    • Network observers. Your network can see that you visited zksend.net, and Blockchair sees your IP with a transaction ID while you track. Use Tor if that matters.
    • Your own patterns. Reusing one address, posting links publicly, or paying from a wallet you also use personally can connect payments to you.

    Terms of use

    zkSEND is a free tool for making Zcash payment links.

    What zkSEND is

    zkSEND builds payment links in your browser. It never holds keys or funds, and it isn't a party, escrow or broker to any payment.

    Payments are final

    A confirmed Zcash transaction can't be reversed. Check addresses and amounts before you send. zkSEND can't recover, refund or cancel a payment.

    No warranty

    The site is provided as-is, with no uptime promise. If it goes offline, nothing you own is affected, because your funds and keys never leave your wallet.

    zkSEND stores no data about you or your payments. See the security page for exactly who can see what.
